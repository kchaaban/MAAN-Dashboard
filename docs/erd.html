Domain diagram

Every foreign key between the 28 domain tables. Entities list their keys and identifying columns; the full column set is in the tables below. A relationship reads parent ‖–o{ child : column; a hollow circle on the parent side means the child’s column is nullable.

PlanningPlaces & geometryOrganisationAllocation (CSV imports)
Cardinality. All 47 foreign keys are many-to-one; there are no join tables in the domain — the Laravel RBAC tables are the only ones.
On delete. 37 of 47 keys are set null; cascade (10) is used only where the child is meaningless without the parent (timing and round_trips → plan_types, plan_logs → plans, mashaers_trips → service_centers, users → types, RBAC pivots).
Identity. Every domain table uses a uuid primary key. Unique constraints exist only on countries, roles, permissions, transport_types.code and transport_companies.name.

How a plan points at places

The diagram above can’t show the most important edges, because they aren’t foreign keys. A plan’s start, end and parking are type-discriminated pairs: a *_type string names the table and an *_id uuid the row. Nothing in the database enforces them; plan_show_view, final_plan_view and the dashboard resolve them by unioning the place tables.

Notes for whoever changes this schema

Polymorphic references are unconstrained

plans.start_point_*, end_point_*, get/set_parking_* and the RBAC model_* pairs have no foreign keys. A deleted camp or drop-off leaves dangling plan rows; the views hide them with LEFT JOINs.

plans.transport_company_id is orphaned

Its target was the old contract table, retired and kept as transport_companies_bak (no primary key). Today’s transport_companies is a different table — the renamed transports name list — and nothing references it. The column stays because plan_show_view selects it; a plan’s suppliers come from mashaers_trips per service centre.

camps carries four path roles

path_entrance_id (entrance → camp, Mina only: 628/630 set, Arafat 0/703), path_camp_id (Mina → Arafat, shared by 627 same-label camp pairs), path_dropoff_id (Arafat camp → Muzdalifah drop-off, 698/703), path_residence_id (unused). drop_off_area_id was added for efada generation; 674/703 Arafat camps are set.

mashaers_trips is a bus roster

One row per bus dispatched to a centre: bus_id, transport type, supplying company. Rows cascade with their service centre. It replaces the contract-style table that was retired.

assign_camps / assign_residences were swapped into their right names

Until 2026-09-21 the per-camp allocation lived in assign_data and the residence list in assign_camps. They now match the API datasets (assign-camps, assign-residences); constraint names were renamed with them.

No uniqueness where the import relies on it

Nothing prevents two service_centers with the same (company_id, office_number) or two service_companies with the same name; the CSV import matches by exactly those and takes the first hit with a warning.

Config tables with duplicates

round_trips holds several rows for (efada, ترددي); the newest updated_at wins. timing has three placeholder 01:01–01:01 rows for efada period 1 beside the real window. periods should be ordered by code, not name.

Text where numbers are meant

assign_residences.haj_count/tarwia/direct_taseed, round_trips.round_trip, plans.period and camps.gate_lat/gate_lon (three coordinate conventions mixed) are varchar or inconsistently encoded; readers cast and normalise.

Shared residences

A residences row is referenced by plans of up to 13 different service centres — one building housing several companies’ pilgrims — so start-point uniqueness is not per centre.
